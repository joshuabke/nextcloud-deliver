# Deliver v2 — Spec

Milestone: **0.2.0** (first working release of the rewrite; 1.0.0 is App Store submission).
Vocabulary: [CONTEXT.md](../CONTEXT.md). Decisions with lasting consequences: [docs/adr](./adr).

## Problem Statement

Editors deliver cuts to clients and colleagues and need frame-accurate feedback on them. Frame.io does this well but is a paid SaaS that copies the media out of the editor's own storage; Clapshot is self-hosted but a separate silo with its own uploads and users. Editors who already keep their material in Nextcloud want the review to happen where the files already are: the cut lands in a synced folder, everyone who may see the folder can comment, outsiders get a link, and the comments come back into the NLE as markers. The existing Deliver 0.1.x prototype does not deliver that: comments are tied to share tokens and vanish with them, anyone with a link can edit anyone's comment, password protection is a stub, the frontend stack is end-of-life, and the player lived inside the Files sidebar, which never worked well.

## Solution

Deliver becomes a proper Nextcloud app, rebuilt from scratch, in which media files in Files are enabled for review: the folder a file lives in becomes a Project, the enabled file becomes an Asset, and a whole folder can be switched to Auto Intake so that every media file in it counts. Iterations of a cut form a Version Stack, and Members (whoever Files lets into the folder) and Reviewers (whoever opens a Nextcloud Share Link that a Member switched review on for) leave Comments anchored to Frames or Ranges. Browser-unfriendly sources get Proxies, Thumbnail Strips and Waveforms generated by ffmpeg in the background when ffmpeg is available. Comments export as EDL, FCP7 XML, FCPXML or CSV per Version. Members get Nextcloud notifications, Reviewers get a Personal Link that keeps their identity forever. Reviewing outsiders arrive through Nextcloud's own Share Links (ADR 0004); Deliver adds a Review button to the shared file list rather than a second kind of link. Files stays the source of truth; Deliver stores only review state.

## User Stories

### Projects and Assets

3. As a Member, I want switching Auto Intake off to keep the Assets it collected and hand the per-file choice back to me, so that the two ways of enabling never fight over one folder.
4. As a Member, I want to take a single file out of Deliver after a confirmation, so that its review data is cleaned up while the file itself stays.
5. As a Member, I want the Deliver app page to list every Project I can access, so that I have one place to find reviews.

8. As a Member, I want a Project to have a timecode display setting (SMPTE, frames, seconds), so that every viewer sees the format my team works in.

## Implementation Decisions

### Repository and stack

- Fresh rewrite on branch `v2` in a worktree; current uncommitted work is committed to main and main is tagged `legacy-0.1.6` before the rewrite lands. Nothing from 0.1.x is inherited; the EDL generator and any useful test ideas are re-read, not copied.
- Backend: Nextcloud app framework, PHP 8.2+, minimum Nextcloud 33: the Files sidebar tab is a web component registered through `@nextcloud/files` (`getSidebar().registerTab`), which exists from 33 on, and @nextcloud/vue 9 needs 31 or newer anyway; older releases are end of life. Frontend: Vue 3, @nextcloud/vue 9, Pinia, Vite via @nextcloud/vite-config. English source strings with `t()`, German translation shipped.
- App id stays `deliver`, author Joshua Böke, repository github.com/joshxtra/nextcloud-deliver (remote switched to SSH).
- Versioning restarts at 0.2.0. No signed release workflow yet.

### Domain model and persistence

Files is the source of truth (ADR 0002). Deliver's tables hold only review state:

- **Project**: folder file id, owner user id, Auto Intake flag, default fps, timecode display mode, created at. The row is created implicitly when the first file in the folder is enabled, and explicitly when a Member switches the folder to Auto Intake. Nesting is rejected at creation time by walking ancestors. Membership is never stored; it is derived per request from the current user's access to the folder.
- **Asset**: project id, display name (derived from the newest Version's filename unless overridden), parent folder file id. An Asset exists for a file a Member enabled, or for every media file in the folder while Auto Intake is on; taking a file out of Deliver deletes the Asset with its Versions and Comments after a confirmation.
- **Version**: asset id, file id, Version Number (integer, unique per Asset), media metadata (fps as rational, drop-frame flag, start timecode in frames, duration in frames, width, height, has video, has audio), state (ready, missing, purged), derived-media state per kind (none, queued, running, ready, failed with message).
- **Comment**: version id, parent comment id (nullable, one level), author reference (user id or reviewer id), in frame, out frame (nullable), body, resolved flag, created and updated timestamps. Frames are stored at the Version's fps; seconds are never persisted. An audio-only Version has no frame rate of its own and keeps the Project's default it was probed with, so its Frames do not change meaning later; a Broadcast WAV's time reference becomes its start timecode.
- **Review flags on a share**: Deliver stores nothing of its own for a Share Link. Whether a share is a review surface (`deliver/review`, off unless set), whether Reviewers may comment (`deliver/comment`) and whether older Versions accept Comments (`deliver/older`) are Nextcloud share attributes, so they are created, copied and deleted with the share. Password, expiry, revocation and "hide download" are the share's own properties (ADR 0004).
- **Reviewer**: project id, name, email (nullable), secret key, created at. A Personal Link is the share URL plus the Reviewer's key. Reviewers are never deleted while they have Comments; revoking a Share Link does not touch them, and a Member can issue a fresh Personal Link for an existing Reviewer under a new Share Link.
- **Seen state**: per person (user id or reviewer id) per Version, the timestamp up to which Comments have been on screen. Everything created after it is Unseen.
- **Project mute**: per user id per project.
- **Job**: kind (probe, proxy, thumbnails, waveform), version id, state, progress, attempts, stderr tail, timestamps. One table for background jobs and the optional worker; designed so an external worker can claim rows later without a schema change (ADR 0003).

File identity is always the Nextcloud file id, so renames and moves inside the Project are free. A move out of the Project or to trash sets the Version to Missing and notifies; permanent deletion purges Version and Comments; permanent deletion of the Project folder purges the Project.

### Discovery and stacking

- A file listener plus a periodic scan job keep Assets in sync. While Auto Intake is on, every new video or audio file in the folder becomes an Asset with Version 1 unless the filename convention matches; without it, files become Assets only when a Member enables them and the listener merely follows moves, renames and deletions of the files already enabled.
- Convention parser: base name plus a suffix of the form `_v3`, `-v03`, ` v3`, `V3` (case-insensitive, optional separator, optional zero padding) before the extension. If exactly one Asset with that base name exists in the same folder, the file is stacked automatically at that Version Number (or next free number on collision), and the Version carries an undo mark until a Member takes note. Otherwise nothing is stacked and the app page offers the candidates for one click; the offer is derived from the Assets on screen, never stored, so it cannot go stale.
- Stacks are always explicit rows; renaming a file never regroups anything.
- Drop upload in the app writes the file into the previous Version's folder through the normal Nextcloud upload endpoint and then stacks it explicitly.

### Media metadata and derived media

- Probe order: ffprobe when present; otherwise browser-side detection on first open, persisted server-side; otherwise the Project default fps. Members can override fps and start timecode per Version, which re-anchors nothing (frames stay frames) but changes display and export.
- Proxy: one H.264/AAC MP4 at the source frame rate (VFR conformed to average), capped at the configured resolution measured on the short side (1080p is 1920×1080 and 1080×1920 alike), CRF around 20, one-second keyframe interval, faststart. Sources browsers play (H.264/AAC MP4, WebM) always play as the original by default, at any size; they get a Proxy only when they exceed the cap, as a lighter choice the player can switch to at the same Frame. For every other source the Proxy is the only playable rendition.
- Thumbnail Strip: WebP sprite plus JSON index, roughly one frame per second, capped by the admin setting.
- Waveform: peaks JSON computed from raw PCM via ffmpeg, no extra binaries. Generated for every Version with audio.
- Storage in `appdata_deliver/<version id>/`. Served through a range-capable streaming endpoint for both Members and Reviewers.
- Jobs run in Nextcloud's background job system, one ffmpeg at a time by default, with the optional `occ deliver:worker` loop and `occ deliver:regenerate`.
- Admin settings: ffmpeg path, ffprobe path, max parallel jobs, max resolution, thumbnail cap, hardware encoder with device path (probed on save), extra ffmpeg args, plus a read-only status panel.

### Permissions

- Read on the folder: view, comment, reply, edit and delete own Comments, export view. A Comment that someone else has replied to is deleted only with write access, so nobody deletes another person's Reply along with their own Comment.
- Write on the folder: everything above plus switch review on a Share Link and set its flags, invite Reviewers, enable and disable files, stack and unstack, set Version Numbers, override metadata, resolve and unresolve, delete any Comment, regenerate derived media, export, change Project settings, remove the Project.
- Reviewer (through a Share Link with `deliver/review` on): view, comment and reply when the share allows, edit and delete own (with the same rule for Comments others replied to), download the original unless the share hides downloads. Never resolve, never see the Project's other Assets beyond the share.
- Deliver never enforces a password of its own: it points out a review Share Link without one, and an admin who wants the rule enforces it with Nextcloud's password policy for link shares.
- A Share Link without the review flag is an ordinary Nextcloud link: no Review button, no Comments, no reviewer session. Enabling a file for review never changes what an existing link shows.
- A logged-in non-Member opening a Share Link becomes a Reviewer with the display name prefilled; a Member is redirected to the app view.
- The public review route extends `AuthPublicShareController`, so the share's password prompt and expiry are enforced by core before Deliver runs; Deliver never stores a token or a password hash.
- Reviewer sessions are a signed cookie holding the reviewer key; it never expires. The Personal Link re-establishes it on any device.

### API

One versioned REST surface under the app, used by the app page, the Files sidebar tab and the public review page alike, with two authentication modes: Nextcloud session for Members and share token plus reviewer key for Reviewers. Resources: projects, assets, versions, comments, review shares, reviewers, exports, media streams, jobs, admin settings. A single `changes?since=` endpoint per Version returns new and changed Comments, Replies, resolves, and Version state so the client polls one thing every few seconds (backgrounded tabs poll slower). The design leaves room for notify_push later.

### Frontend surfaces

- App page: Project list as tiles, without app navigation (story 97); Project view (Assets with stack badges, processing state, comment counts and Unseen Comments, filters and sorting, and an app navigation of its folders, Share Links and Personal Links); Review view without app navigation (player, marker strip, comment panel, version switcher, export menu, link management drawer).
- Public review page: the same Review view under the share token, with Reviewer identity prompt, Personal Link display and reduced controls. Deliver loads its script into Nextcloud's own public share page through `OCA\Files_Sharing\Event\BeforeTemplateRenderedEvent` and registers a Review file action there for shares carrying the review flag, so the Reviewer goes from the shared file list into the player in one click. Shares without the flag load nothing of Deliver's.
- Files sidebar tab "Deliver": on a media file, the review toggle, stack position, comment count and "Open in Deliver"; on a folder, the Auto Intake toggle and the Project settings. Files action "Open in Deliver" on video and audio. The player never renders inside the sidebar.

### Export

- CMX3600 EDL with one event per Comment, Range duration for Ranges, comment text and appended Replies in the note lines.
- FCP7 XML with markers on a single clip.
- FCPXML 1.10 with markers on a single clip in a project, times as rational seconds; the clip comes in offline and relinks to the original, a resolved Comment is a completed to-do marker.
- CSV with frame in, frame out, timecode in, timecode out, author, body, replies, resolved.
- For audio-only Versions, marker files for audio workstations instead, since few of them import text:
  - WAV with embedded markers: a copy of the audio (converted to 24-bit PCM when it is not WAV) with a `cue ` chunk and `LIST`/`adtl` labels, Ranges as `ltxt` regions; a BWF original keeps its time reference, so the markers land at its place in the session. Read by Logic Pro (Import Marker from Audio File), Cubase and Nuendo (Extract Markers from Wave File) and Sequoia.
  - Standard MIDI File with marker meta events at a constant 120 BPM, a Range as a start and an end marker. Read by Pro Tools (as Memory Locations), Cubase, REAPER and Logic Pro (File › Open).
  - REAPER's Region/Marker Manager CSV, Ranges as regions.
  - Ableton Live imports no markers and opens only sets its own version wrote: the Member uploads a Live Set and gets it back with the Comments as locators, in beats at the set's tempo.
  - The CSV above doubles as Nuendo's CSV marker import. Pyramix has no documented marker import; the WAV is the one to try there.
- All per Version, embedded start timecode by default, zero-based switch, unresolved-only toggle.

### Notifications

Nextcloud notification app for Members: new Comment, new Reply, new Version, auto-stack, Missing. Respect per-Project mute. Email to Reviewers with an email only on Replies to their Comments; when the instance has no mail configured the share's Deliver settings say so and nothing is sent.

## Testing Decisions

A good test exercises Deliver the way a person or an NLE does and asserts on what they would see: HTTP responses, rendered UI, exported files, generated media. Tests never assert on private state, table rows, or which class was called.

Seams, from highest to lowest, with the intent to keep them to two:

1. **HTTP API inside a real Nextcloud** — PHPUnit integration tests booted with the Nextcloud test bootstrap in the dev container. Every backend story is tested here: permissions by acting as different users and reviewer keys, stacking by creating files through the Nextcloud filesystem, Missing and purge by moving and deleting files, exports by parsing the returned EDL/XML/CSV, derived media by running real ffmpeg on tiny fixture clips and asserting the resulting Proxy's fps and duration. Pure PHP units (timecode math, filename convention parser, EDL/XML writers) get plain PHPUnit unit tests as a second tier because they are cheap and precise.
2. **Browser via Playwright** against the dev container — the review flows: enable a file from the sidebar, open Review view, frame step and comment, Range comment, reply, resolve, badge on Unseen, Reviewer flow from a Share Link's file list through the Review button and a Personal Link on a fresh browser context, export download, sidebar tab. Vitest component tests are limited to pure client logic (timecode formatting, keyboard map, polling merge), not to component rendering.

Prior art in the repo is thin: two Jest component tests and a login-only Playwright spec from 0.1.x; they are references for tooling only. Fixtures: a 2-second 25 fps H.264 clip, a 23.976 fps clip, a ProRes clip, and a WAV, all under a second of audio, generated by ffmpeg in a setup script rather than committed.

CI runs php-cs-fixer, psalm, PHPUnit (unit and integration), Vitest and Playwright on every push using a throwaway Nextcloud container with ffmpeg.

## Out of Scope

- Digest emails.
- Frame.io's project furniture: workspaces and roles of Deliver's own, metadata fields (status, assignee, rating, keywords), collections, cover images, and folder management inside Deliver. Nextcloud sharing and Files do those; Approvals and Due Dates carry the status.
- PDFs as Assets.
- Watermarks burned into the picture (the Watermark is an overlay in the player).
- Adaptive streaming, multiple Proxy renditions, 4K Proxies.
- On phones: comparing Versions, Exports, managing Version Stacks and upload by drag and drop; they stay on larger screens.
- External or GPU-farm transcoding workers over HTTP (job table is ready for it).
- Direct push of markers into DaVinci Resolve.
- Signed App Store release workflow and the certificate.
- Deploying Nextcloud on the Proxmox NAS; the repo ships only a generic `deploy/` compose example with ffmpeg and `/dev/dri`.

## Further Notes

- The user's own target host is a Proxmox box with an i9-9900K and an Intel UHD 630, so VAAPI is the hardware encoder to verify first; software x264 remains the default everywhere.
- Frame anchors rely on the Proxy having exactly the source frame rate; this is a correctness invariant, not an optimisation.
- Ranges are inclusive of the out Frame.
- Comment sort default is by Frame with a newest-first switch; the Unseen badge exists precisely because Frame order hides recency.
- Timecode display mode is a Project setting; the player offers a session-local override that does not persist.
- Reviewer identity is permanent by design: a Personal Link is the credential. Members are told this when they create one so they hand it to one person only.
