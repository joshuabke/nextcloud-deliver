# Deliver v2 — Spec

Milestone: **0.2.0** (first working release of the rewrite; 1.0.0 is App Store submission).
Vocabulary: [CONTEXT.md](../CONTEXT.md). Decisions with lasting consequences: [docs/adr](./adr).

## Problem Statement

Editors deliver cuts to clients and colleagues and need frame-accurate feedback on them. Frame.io does this well but is a paid SaaS that copies the media out of the editor's own storage; Clapshot is self-hosted but a separate silo with its own uploads and users. Editors who already keep their material in Nextcloud want the review to happen where the files already are: the cut lands in a synced folder, everyone who may see the folder can comment, outsiders get a link, and the comments come back into the NLE as markers. The existing Deliver 0.1.x prototype does not deliver that: comments are tied to share tokens and vanish with them, anyone with a link can edit anyone's comment, password protection is a stub, the frontend stack is end-of-life, and the player lived inside the Files sidebar, which never worked well.

## Solution

Deliver becomes a proper Nextcloud app, rebuilt from scratch, in which media files in Files are enabled for review: an enabled file becomes an Asset, in a Project or in No Project, and a whole folder can become a Folder Project on Auto Intake so that every media file in it counts. Projects collect files from anywhere without moving them (ADR 0009). Iterations of a cut form a Version Stack, and Members (whoever Files lets open the file) and Reviewers (whoever opens a Project Link a Member made) leave Comments anchored to Frames or Ranges. Browser-unfriendly sources get Proxies, Thumbnail Strips and Waveforms generated by ffmpeg in the background when ffmpeg is available. Comments export as EDL, FCP7 XML, FCPXML or CSV per Version. Members get Nextcloud notifications, Reviewers get a Personal Link that keeps their identity forever. Reviewing outsiders arrive through Project Links, Deliver's own review links for a whole Project or picked Assets (ADRs 0010 and 0011); sharing in Files stays plain Nextcloud sharing. Files stays the source of truth; Deliver stores only review state.

## User Stories

### Projects and Assets

3. As a Member, I want switching Auto Intake off to keep the Assets it collected and hand the per-file choice back to me, so that the two ways of enabling never fight over one folder.
4. As a Member, I want to take a single file out of Deliver after a confirmation, so that its review data is cleaned up while the file itself stays.

6. As a Member, I want a Project to show its folder tree with every enabled file as an Asset, so that subfolders keep their meaning.

9. As a Member, I want to remove a Project after a confirmation, its Assets going to No Project with their review data, so that reorganising never loses Comments.
10. As a Member, I want a folder inside a Folder Project to be refused as a new Folder Project, so that Auto Intake never fights over a file.
11. As a Member, I want a Folder Project whose folder was deleted to lose its folder and Auto Intake but keep its Assets, so that trash restore and a new home keep my comments.

## Implementation Decisions

### Repository and stack

- A rewrite from scratch. Nothing from 0.1.x is inherited; the EDL generator and any useful test ideas are re-read, not copied.
- Backend: Nextcloud app framework, PHP 8.2+, minimum Nextcloud 33: the Files sidebar tab is a web component registered through `@nextcloud/files` (`getSidebar().registerTab`), which exists from 33 on, and @nextcloud/vue 9 needs 31 or newer anyway; older releases are end of life. Frontend: Vue 3, @nextcloud/vue 9, Pinia, Vite via @nextcloud/vite-config. English source strings with `t()`, German translation shipped.
- App id stays `deliver`, author Joshua Böke, repository github.com/joshuabke/nextcloud-deliver.
- Versioning restarts at 0.2.0. No signed release workflow yet.

### Domain model and persistence

Files is the source of truth (ADR 0002). Deliver's tables hold only review state:

- **Project** (ADR 0009): name, folder file id (nullable; set for a Folder Project, which takes the folder's name), owner user id (who made it), Auto Intake flag (Folder Projects only), default fps, timecode display mode, created at. Only made on purpose: by name, or from a folder (Auto Intake on). Folder Projects do not nest. Membership is never stored; it is derived per request from access to each Version's file.
- **Asset**: project id (nullable: No Project), enabled by (user id, for No Project), display name (derived from the newest Version's filename unless overridden), parent folder file id. An Asset exists for a file a Member enabled, or for every media file in a Folder Project's folder while Auto Intake is on and no Project holds it; taking a file out of Deliver deletes the Asset with its Versions and Comments after a confirmation. Assigning an Asset to a Project, or to none, moves no file.
- **Version**: asset id, file id (unique: a file is one Version at most), Version Number (integer, unique per Asset), media metadata (fps as rational, drop-frame flag, start timecode in frames, duration in frames, width, height, has video, has audio), state (ready, missing, purged), derived-media state per kind (none, queued, running, ready, failed with message).
- **Comment**: version id, parent comment id (nullable, one level), author reference (user id or reviewer id), in frame, out frame (nullable), body, resolved flag, created and updated timestamps. Frames are stored at the Version's fps; seconds are never persisted. An audio-only Version counts in milliseconds: its frame rate is 1000/1 whatever the Project's, so a Frame is a millisecond, its Frames never change meaning with the Project setting, and Takes line up to the millisecond (ADR 0007). Shown as timecode or frames, its position is converted to the Project's frame rate for display only. A Broadcast WAV's time reference becomes its start timecode.
- **Reviewer**: owner user id (the Member who invited them), name, email (nullable), secret key, created at. A Reviewer has a Personal Link through every Project Link of their owner. A Personal Link is the link's URL plus the Reviewer's key. Reviewers are never deleted while they have Comments: removing one clears their key, so their Personal Links stop working and they leave every list while their Comments keep the name; deleting a Project Link does not touch them, and a Member can issue a fresh Personal Link for an existing Reviewer under a new Project Link.
- **Project Link**: Project (null: No Project), owner user id (the Member who made it), token, label, description, password hash (`IHasher`), expiry date, the picked Assets (none: the whole Project; on No Project at least one, and an Asset leaves the link once it joins a Project), flags for comments, older Versions, Watermark, download, only the newest Version and paused. Removed with its Project (ADRs 0010 and 0011).
- **Link activity**: token, Reviewer (nullable), what happened (opened, viewed a Version, downloaded it), Version, time. Kept per token.
- **Seen state**: per person (user id or reviewer id) per Version, the timestamp up to which Comments have been on screen. Everything created after it is Unseen.
- **Project mute**: per user id per project, or for No Project.
- **Job**: kind (probe, proxy, thumbnails, waveform), version id, state, progress, attempts, stderr tail, timestamps. One table for background jobs and the optional worker; designed so an external worker can claim rows later without a schema change (ADR 0003).

File identity is always the Nextcloud file id, so renames and moves are free and never change a Version's Project. A move to trash sets the Version to Missing and notifies; permanent deletion purges Version and Comments. A Folder Project whose folder is deleted becomes a plain Project. Attachments live in app data under the Comment.

### Discovery and stacking

- A file listener plus a periodic scan job keep Assets in sync. While Auto Intake is on, every new video or audio file in the folder that no Project holds becomes an Asset with Version 1 unless the filename convention matches; otherwise files become Assets only when a Member enables them, and the listener merely follows moves, renames and deletions of the files already enabled. The scan checks every Version's file by id, wherever it lies.
- Convention parser: base name plus a suffix of the form `_v3`, `-v03`, ` v3`, `V3` (case-insensitive, optional separator, optional zero padding) before the extension. If exactly one Asset with that base name exists in the same folder and the same Project (or No Project), the file is stacked automatically at that Version Number (or next free number on collision), and the Version carries an undo mark until a Member takes note. Otherwise nothing is stacked and the app page offers the candidates for one click; the offer is derived from the Assets on screen, never stored, so it cannot go stale.
- Stacks are always explicit rows; renaming a file never regroups anything.
- Drop upload in the app writes the file into the previous Version's folder through the normal Nextcloud upload endpoint and then stacks it explicitly.

### Media metadata and derived media

- Probe order: a Sidecar entry for the file when there is one (ADR 0005); then ffprobe when present; otherwise Deliver's own container reader, which takes the frame rate, duration and start timecode from a MOV or MP4 and the time reference from a Broadcast WAV; otherwise the Project default fps and start 0. Audio-only Versions always count in milliseconds. Members can override fps and start timecode per Version, which re-anchors nothing (frames stay frames) but changes display and export.
- Proxy: one H.264/AAC MP4 at the source frame rate (VFR conformed to average), capped at the configured resolution measured on the short side (1080p is 1920×1080 and 1080×1920 alike), CRF around 20, one-second keyframe interval, faststart. Sources browsers play (H.264/AAC MP4, WebM) always play as the original by default, at any size; they get a Proxy only when they exceed the cap, as a lighter choice the player can switch to at the same Frame. For every other source the Proxy is the only playable rendition.
- Thumbnail Strip: WebP sprite plus JSON index, roughly one frame per second, capped by the admin setting.
- Waveform: peaks JSON computed from raw PCM via ffmpeg, no extra binaries. Generated for every Version with audio. Without ffmpeg, a WAV's peaks are read from its PCM on the server, and other audio is decoded once by the first Member's browser, which hands peaks and duration to the server; it never overrides a Waveform the server made.
- Storage in `appdata_deliver/<version id>/`. Served through a range-capable streaming endpoint for both Members and Reviewers.
- Jobs run in Nextcloud's background job system, one ffmpeg at a time by default, with the optional `occ deliver:worker` loop and `occ deliver:regenerate`.
- Admin settings: ffmpeg path, ffprobe path, max parallel jobs, max resolution, thumbnail cap, hardware encoder with device path (probed on save), extra ffmpeg args, plus a read-only status panel.

### Takes and Sidecar

- Sidecar: `deliver.json` in the folder it describes, written by the delivering tool after the files and before they are enabled. Format:
  ```json
  {
    "deliver": 1,
    "takes": true,
    "files": {
      "RP12.mp3": {
        "start": 252.35,
        "duration": 183.21,
        "lane": 3,
        "waveform": { "rate": 50, "peaks": [0.012, 0.431, 0.998] }
      }
    }
  }
  ```
  `start` is the Session Time of the first sample in seconds and becomes the start Frame in milliseconds; `duration` in seconds; `lane` orders Takes and is ignored elsewhere; `takes` is present only on a Take Folder's Sidecar; unknown keys are ignored. A Sidecar entry is the probe result for its file (audio only, no video) and is re-read when the Sidecar changes. Limits, since anyone with write access writes it: a Sidecar of at most 5 MiB, `rate` at most 100, and no more peaks than `duration` × `rate`; a Sidecar or entry over them is ignored and the file is probed instead.
- Waveform: the peaks JSON gains an optional `rate` (peaks per second). Without it, the 2000 buckets across the duration as before; a Sidecar Waveform is stored as is, so zoomed Take lanes stay sharp.
- Take alignment rests on start Frames, which for audio are milliseconds, so Takes line up to the millisecond whatever the Project's frame rate. Playback position itself is continuous.
- Delivering again: a file written again in place keeps its file id, Version and Comments, and Deliver re-reads it (Sidecar first) and rebuilds its derived media. Replacing the file of a Version that has Comments is the exception and needs an explicit confirmation: Deliver's own upload asks, and a delivering tool asks before it overwrites, after reading the Version's Comments through the OCS API; without the confirmation it delivers a new Version instead, or for a Take skips it (ADR 0008). Writes from the Files app or a sync client cannot be asked about and are taken as they come.
- Take comparison: a view of its own over the Takes of one Take Folder, opened from the Project view, the Asset menu and a link's landing page, where a Take Folder is one entry. One audio element plays the selected Take; switching only happens while stopped. Comments are ordinary Comments on each Take's one Version (ADR 0008), anchored to a Frame; Ranges are not offered here.

### Permissions

- Rights follow each Version's file (ADR 0009); a Project shows each person the Assets whose files they can open.
- Read on the file: view, comment, reply, edit and delete own Comments, export view. A Comment that someone else has replied to is deleted only with write access, so nobody deletes another person's Reply along with their own Comment.
- Write on the file: everything above plus invite Reviewers, enable and disable files, assign them to a Project, stack and unstack (write on both files), set Version Numbers, override metadata, resolve and unresolve, delete any Comment, regenerate derived media, export.
- Project Links: a Member makes them on a Project they see, or on No Project; a link shows only files its Member may reshare (ADR 0010), and only that Member changes or deletes it.
- A Folder Project's name follows its folder and its settings follow write access to the folder; any other Project's name, settings and removal belong to the Member who made it.
- Reviewer (through a live Project Link): view, comment and reply when the link allows, edit and delete own (with the same rule for Comments others replied to), download the original unless the link hides downloads. Never resolve, never see Assets the link does not show.
- Deliver never enforces a password of its own: it points out a review link without one, and an admin who wants the rule enforces it with Nextcloud's password policy, which applies to the passwords of Project Links as to Nextcloud's own.
- Sharing in Files makes an ordinary Nextcloud link: Deliver adds nothing to it, no Comments, no reviewer session (ADR 0011).
- A logged-in non-Member opening a Project Link becomes a Reviewer with the display name prefilled; a Member is redirected to the app view.
- The public review route extends `AuthPublicShareController`, so the link's password prompt and expiry are enforced by core before Deliver runs. Deliver stores tokens and password hashes (`IHasher`) for its Project Links (ADRs 0010 and 0011); a Project Link shows only files its Member may reshare.
- Reviewer sessions are a signed cookie holding the reviewer key; it never expires. The Personal Link re-establishes it on any device.

### API

One versioned REST surface under the app, used by the app page, the Files sidebar tab and the public review page alike, with two authentication modes: Nextcloud session for Members and link token plus reviewer key for Reviewers. Resources: projects, assets, versions, comments, Project Links, reviewers, exports, media streams, jobs, admin settings. A single `changes?since=` endpoint per Version returns new and changed Comments, Replies, resolves, and Version state so the client polls one thing every few seconds (backgrounded tabs poll slower). The design leaves room for notify_push later.

### Frontend surfaces

- App page: Project list as tiles, without app navigation (story 97); Project view (Assets with stack badges, processing state, comment counts and Unseen Comments, filters and sorting, a dialog from each Asset's menu to manage its Version Stack, where an automatic stack is kept or undone, and an app navigation of its folders, links and Reviewers; a link's settings, Reviewers and activity open in a dialog, and only there is a link deleted or a Reviewer removed); Review view without app navigation (player, marker strip, comment panel, version switcher, export menu, a Share dialog with the Project Links that show the Version's Asset); managing a Version Stack is not part of it.
- Public review page: the same Review view under the link's token, with Reviewer identity prompt, Personal Link display and reduced controls; a link with several Assets opens on a grid of them under its description, one with a single Asset straight in the player (story 125). The grid names the Reviewer once they have a name, offers each original and, as one ZIP, the newest Version of every Asset or of those picked with a checkbox where the link allows downloads, and shows a frame of the video itself where Nextcloud renders no still (no ffmpeg on the server). Nextcloud's own public share page carries nothing of Deliver's (ADR 0011).
- Files sidebar tab "Deliver": on a media file, the review toggle, stack position, comment count and "Open in Deliver"; the Project it is in, to pick or clear; on a folder, a button that makes it a Folder Project with a switch for Auto Intake, on unless switched off first, and its settings; the Project Links that show the file's Asset, or a Folder Project's links on its folder, each with copy and delete buttons, password, expiry and rights, and a button that makes one for that Asset or Project. Files action "Open in Deliver" on video and audio. The player never renders inside the sidebar.

### Export

- CMX3600 EDL with one event per Comment, Range duration for Ranges, comment text and appended Replies in the note lines.
- FCP7 XML with markers on a single clip.
- FCPXML 1.10 with markers on a single clip in a project, times as rational seconds; the clip comes in offline and relinks to the original, a resolved Comment is a completed to-do marker.
- CSV with frame in, frame out, timecode in, timecode out, author, body, replies, resolved.
- For audio-only Versions, marker files for audio workstations instead, since few of them import text:
  - WAV with embedded markers: a copy of the audio (converted to 24-bit PCM when it is not WAV) with a `cue ` chunk and `LIST`/`adtl` labels, Ranges as `ltxt` regions; a BWF original keeps its time reference, so the markers land at its place in the session. Read by Logic Pro (Import Marker from Audio File), Cubase and Nuendo (Extract Markers from Wave File) and Sequoia.
  - Standard MIDI File with marker meta events at a constant 120 BPM, a Range as a start and an end marker. Read by Pro Tools (as Memory Locations), Cubase, REAPER and Logic Pro (File › Open).
  - REAPER's Region/Marker Manager CSV, Ranges as regions.
  - Ableton Live imports no markers and opens only sets its own version wrote: the Member uploads a Live Set and gets it back with the Comments as locators, in beats at the set's tempo.
  - The CSV above doubles as Nuendo's CSV marker import. Pyramix has no documented marker import; the WAV is the one to try there.
- All per Version, embedded start timecode by default, zero-based switch, unresolved-only toggle.

### Notifications

Nextcloud notification app for Members: new Comment, new Reply, new Version, auto-stack, Missing. Respect per-Project mute. Email to Reviewers with an email only on Replies to their Comments; when the instance has no mail configured a link's settings say so and nothing is sent.

## Testing Decisions

A good test exercises Deliver the way a person or an NLE does and asserts on what they would see: HTTP responses, rendered UI, exported files, generated media. Tests never assert on private state, table rows, or which class was called.

Seams, from highest to lowest, with the intent to keep them to two:

1. **HTTP API inside a real Nextcloud** — PHPUnit integration tests booted with the Nextcloud test bootstrap in the dev container. Every backend story is tested here: permissions by acting as different users and reviewer keys, stacking by creating files through the Nextcloud filesystem, Missing and purge by moving and deleting files, exports by parsing the returned EDL/XML/CSV, derived media by running real ffmpeg on tiny fixture clips and asserting the resulting Proxy's fps and duration. Pure PHP units (timecode math, filename convention parser, EDL/XML writers) get plain PHPUnit unit tests as a second tier because they are cheap and precise.
2. **Browser via Playwright** against the dev container — the review flows: enable a file from the sidebar, open Review view, frame step and comment, Range comment, reply, resolve, badge on Unseen, Reviewer flow through a Project Link and a Personal Link on a fresh browser context, export download, sidebar tab. Vitest component tests are limited to pure client logic (timecode formatting, keyboard map, polling merge), not to component rendering.

Prior art in the repo is thin: two Jest component tests and a login-only Playwright spec from 0.1.x; they are references for tooling only. Fixtures: a 2-second 25 fps H.264 clip, a 23.976 fps clip, a ProRes clip, and a WAV, all under a second of audio, generated by ffmpeg in a setup script rather than committed.

CI runs php-cs-fixer, psalm, PHPUnit (unit and integration), Vitest and Playwright on every push using a throwaway Nextcloud container with ffmpeg.

## Out of Scope

- Digest emails.
- Frame.io's project furniture: workspaces and roles of Deliver's own, metadata fields (status, assignee, rating, keywords), cover images, and folder management inside Deliver. Nextcloud sharing and Files do those; Approvals and Due Dates carry the status.
- PDFs as Assets.
- Watermarks burned into the picture (the Watermark is an overlay in the player).
- Adaptive streaming, multiple Proxy renditions, 4K Proxies.
- On phones: comparing Versions, Exports, managing Version Stacks and upload by drag and drop; they stay on larger screens.
- External or GPU-farm transcoding workers over HTTP (job table is ready for it).
- Direct push of markers into DaVinci Resolve.
- Ranges, ratings and favourites on Takes; assembling Takes into a cut in the browser.
- Aligning Takes by their audio (they line up only as the recording session placed them).
- The Take comparison on phones.
- Deploying and running a particular Nextcloud server; the repo ships only a generic `deploy/` compose example with ffmpeg and `/dev/dri`.

## Further Notes

- VAAPI (Intel and AMD graphics) is the hardware encoder to verify first; software x264 remains the default everywhere.
- Frame anchors rely on the Proxy having exactly the source frame rate; this is a correctness invariant, not an optimisation.
- Ranges are inclusive of the out Frame.
- Comment sort default is by Frame with a newest-first switch; the Unseen badge exists precisely because Frame order hides recency.
- Timecode display mode is a Project setting for video; audio-only Versions and the Take comparison show `m:ss.mmm`. The player offers a session-local override between them that does not persist.
- Reviewer identity is permanent by design: a Personal Link is the credential. Members are told this when they create one so they hand it to one person only.
